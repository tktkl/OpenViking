# 会话并发

Gateway 可以同时处理不同会话的 Agent 轮次。同一完整 `SessionKey(type, channel_id, chat_id)` 内仍按入队顺序执行，历史、命令和后台回写共用这一顺序。飞书话题沿用渠道已有的 SessionKey 划分方式。

## 启用与回退

在已有 `ov.conf` 中合并以下字段，然后重启 Gateway：

```json
{
  "bot": {
    "agents": {
      "max_concurrent_sessions": 4
    }
  }
}
```

该字段必须是正整数。默认值为 `1`，显式设置 `1` 也使用原来的全局 FIFO：A1、A2、B1 按该顺序入队，就按该顺序执行。大于 `1` 时启用会话调度器，例如 A1 阻塞时 B1 可以先完成，A2 仍等待 A1 完成。

回退时将该值恢复为 `1` 并重启，无须迁移历史文件。此配置在启动时读取，不是运行时热切换。

## 调度与会话控制

- 入站主循环持续读取总线。消息作为数据存入各会话的队列，由固定数量的 worker 执行，不为每条排队消息创建等待 task。
- 一个会话每次执行一项，完成后若还有消息，就重新进入就绪队列尾部。繁忙会话的积压不会占住其他等待 worker。
- 普通消息、无须回复的历史记录、斜杠命令、扩展 `internal_handler` 和内部续办共用会话队列。`before_process` 在真正执行该项时检查，过期续办可以被跳过。
- 会话执行权持续到结果保存、轮次清理和结果入出站总线完成。最终保存开始前会移除该轮次的中断入口，用户中断不能取消最终保存，也不会因此提前执行同会话下一项。
- `interrupt(session_key)` 只取消对应会话的活动用户轮次，并标记调用时已经排队的用户消息；计数覆盖消息总线和调度器，排除内部通知。之后收到的新消息正常执行。
- `steer(msg)` 沿用向当前轮次追加输入的语义，按会话查找活动轮次。追加输入的预处理和中断恢复也由所属轮次负责。
- 单项处理失败会发布该项的错误消息，其他会话及后续消息可以继续执行。退出时先停止入站调度，取消并等待 worker、活动轮次和追加输入预处理，再关闭运行时扩展；既有 Gateway 关闭流程随后关闭 MCP 和沙箱。

队列只限制同时执行的会话数，没有新增积压消息的数量或内存上限。增加并发会提高模型及工具的同时请求数，需要按部署容量选择数值。

## 复用的行为与边界

仍使用一个 AgentLoop、一套 MCP 连接、同一组运行时扩展。服务台识别、可信消息来源、历史预算、工具结果裁剪和沙箱选择沿用既有实现。

出站消息仍经过原来的发送队列和回执处理器，发送 API 的并发度没有增加。会话并发也不会为共享文件、共享沙箱或外部系统自动加锁；这些资源继续遵循各自的访问规则。

本功能没有新增飞书自然语言即时中断入口。现有控制入口调用的 `interrupt`、`steer` 获得了按会话隔离的实现。`process_direct`、Compile 等直接调用接口仍由调用者管理，不自动进入 Gateway 的会话队列。

## 上游合并

此功能从 `bot-main` 的 `fe3dc33a5cdfdc3309af61912f02077668bc03e5` 派生，开发分支为 `codex/vikingbot-session-concurrency`。并发功能的生产改动集中在三个文件：

| 文件 | 需要保留的行为 |
| --- | --- |
| [agent/session_dispatcher.py](../../../vikingbot/agent/session_dispatcher.py) | 固定 worker、按完整 SessionKey 排队、每次一项后轮转、关闭时等待清理 |
| [agent/loop.py](../../../vikingbot/agent/loop.py) | 单独的入站消费；默认串行路径；内部事件同会话排序；按会话和任务身份清理活动状态；中断计数；关闭顺序 |
| [config/schema.py](../../../vikingbot/config/schema.py) | `max_concurrent_sessions` 为正整数且默认 `1` |

上游修改消息入口、活动任务、中断/追加消息或关闭流程时，需要重新对照行为测试。特别检查最终保存前解除中断入口与保存后释放会话执行权两个时点。不要因为文本自动合并成功就省略回归；如果上游提供了等价调度器，先比较同会话顺序和中断语义，再决定迁移。

`agent_bridge` 不包含在此功能提交中。需要组合验证时，在临时工作树中叠加其消息总线/OpenAPI 补丁和扩展文件，运行桥接契约及并发回归，验证后移除临时工作树。

## 验证

在安装测试依赖的环境，从仓库根目录运行：

```bash
PYTHONPATH=bot:. python -m pytest -c bot/pytest.ini \
  bot/tests/test_session_dispatcher.py \
  bot/tests/test_agent_session_concurrency.py \
  bot/tests/test_agent_loop_outcome.py
```

验收使用并发值 `4`，也覆盖默认和显式 `1`、不同并发上限、繁忙会话公平性、中断快照、追加输入、来源和持久历史隔离、命令/后台事件顺序、执行时过期检查、最终保存、失败恢复和退出清理。测试使用事件控制先后顺序，不依赖真实模型、飞书或付费任务。

合并前同时运行服务台、后台任务、OpenAPI 控制、发送回执、消息来源及上下文预算回归，参见[上游合并影响](../extensions/upstream-merge-impact.md)。
